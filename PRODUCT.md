# Product

## Register

brand

## Users

Developers deciding whether to put forges-proxy in front of their forge access: people building web apps, CI bots, AI agents, or non-JS services that read from GitHub, GitLab, Tangled, and other forges. They meet it in the README on GitHub, skimming, in light or dark mode, and want to know in seconds what it does and whether it fits.

## Product Purpose

A self-hosted API gateway for code forges: it holds the forge tokens, caches public reads at the CDN, rate-limits callers, and serves the `forges` API over HTTP with a typed client and an OpenAPI document. Success is a reader who understands the shape of it from the server diagram and the first screen of the README, and deploys their own.

## Brand Personality

Plain, precise, technical. Reads like good API docs: factual, quiet, confident. Specific nouns and real numbers over adjectives.

## Anti-references

- SaaS landing pages: hero headlines, feature-card grids, marketing polish.
- Enterprise architecture slides: boxes-and-arrows deck look, clip-art icons.
- The generic AI look: purple or indigo accents, gradients, tracked uppercase eyebrows everywhere, aphoristic copy.

## Design Principles

- Show, don't tell: a diagram should carry the idea without its caption.
- Precision over persuasion: state what it does, with real names and numbers.
- One idea per surface: every element earns its place or goes.
- Docs, not ads: it should sit naturally in a GitHub README.

## Accessibility & Inclusion

Images carry full alt text. Text meets WCAG AA contrast in both light and dark renders. Meaning never depends on colour alone.
